# 驗收與證據邊界

[English](validation.md) · [專案首頁](../README.zh-TW.md)

## 目前可以說什麼

Mac agent 經 Windows RStudio／ClaudeR、R、MplusAutomation 呼叫 Mplus 的操作路線，已在來源部署中執行過真實科研批次。這裡保留的是可重用經驗；私有科研輸出、機器身分與工作階段記錄不隨本倉庫發布。

這段經驗**不能**直接證明公開套件在每一台新機器都已通過。請核對使用 revision 的 CI 與該版本驗收記錄。不能只憑文檔宣稱新機 Windows 驗收通過、整夜穩定、所有 agent 自動載入或科學驗收完成。

## 分層驗收

| 層次 | 必要證據 |
| --- | --- |
| 原始碼與安裝 | 精確 revision、本機離線檢查、安裝回執、預期連結與檔案集合 |
| 網路 | 到正確服務的可信路由、正確監聽介面及允許清單 |
| 命令通道 | 新鮮且簽章有效的 Windows 輪詢，以及新提交的無副作用命令回執 |
| RStudio 路線 | discovery、PID／出生時間／父程序／監聽一致，指定工作階段真實回應 |
| 長工作 | 原提交意圖與 job ID、進度、持久終態、執行時間預算 |
| 結果傳輸 | 明確匯出集合、大小、SHA 校驗、本機可用空間核對 |
| 科學結果 | 未變更的設計、實際路線中的軟體／套件版本、收斂及領域獨立核驗 |
| Agent 整合 | 指定 agent 在該環境找到已安裝 skill，並成功呼叫 CLI |

為 Codex、Claude Code、Gemini 或 Antigravity 安裝連結，只證明檔案系統整合，不證明特定版本必然自動載入。其他慣例的 agent 也可明確讀取 `SKILL.md`，再使用同一 CLI。

## 測試

執行前先讀測試。離線解析器、身分狀態與檔案安全測試不連 Windows。`scripts/selftest.sh` 是連線測試，可能建立遠端合成檔案與工作，應在已批准的測試窗口執行。

不要只為安裝宣稱而啟動模型。獲准做引擎測試時，使用合成輸入及有限預算；記錄實際 R 程序與 `packageVersion("MplusAutomation")`，Rscript 與互動 RStudio 可能載入不同套件庫。

通過的說法要附範圍，例如「離線 CLI 測試通過」、「Windows 命令回執已核」、「RStudio HTTP fallback 通過」或「合成模型已核」。HTTP fallback 成功不等於原生 MCP 成功；外層 R job 為 complete，不代表全部批次成員通過。

## 結果與資料邊界

`pull-dir`、`rscript`、`mplus` 會取回選定工作目錄的全部內容，**不會自動排除個體資料或輸入副本**。限制外流的資料應保留在 Windows，以既有本機輸入執行；另建僅含結果的匯出，核完整 manifest，再取回並比較檔案集合與 SHA。傳輸上限及磁碟底線由領域工作流按專案設定。

SHA 證明位元組一致，不證明模型正確。Mplus 正常終止常是必要條件，並非充分科學驗收。負變異數、慢收斂、精度檢查與資訊矩陣警告必須分別處理。

## 效率

分別量測獲窗到提交、Windows 引擎起止、匯出與取回時間；工程耗時與科學引擎耗時都要報。網路 ping 不等於整體任務延遲，某批次引擎時間占比高也不等於相對 Windows 本機 agent 的對照加速。

一次提交可產生有用批次、Mac 同時處理編輯審查時，遠端開發才有優勢。反覆為極短工作做完整傳輸會讓開銷占大部分時間。優化排程時保留原模型與精度要求。
