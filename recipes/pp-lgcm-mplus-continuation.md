# 配方：研究批次的跨機接續與效率

[English](research-batches.en.md) · [RStudio 路線](windows-rstudio-clauder.md)

本頁由真實研究工作提煉，保留通用經驗；檔名為相容舊連結保留。個別研究進度、數值、私有路徑與回執不隨公開套件發布。領域模型規格由 `mplusautomation-guide` 管理，xdev 不另做科學調度器。

## 固定工作契約

接續只需先讀簡短現況交接、QUEUE 及原 job 最新回執，不每次重新讀完整遷移包。固定科學腳本、來源 SHA、預算、已完成成員及待核狀態；程式修改用版本控制，不為每一階段複製一套 runner。

Windows 本機與 Mac 遠端 agent 都使用同一 RStudio／ClaudeR → R → MplusAutomation → Mplus 邏輯。若使用 Python 監督器，應由已批准的領域 R 路線呼叫；Python 直接啟動引擎不能冒充指定路線。

## 獲窗後立即提交

先固定已批准 PLAN、腳本 SHA、RStudio 身分、剩餘預算與原提交正文，形成 READY。領域工作流可由本機輕量觀察器等待共享 grant；收到後持久寫入 claim，再提交一次原請求。Windows 真正進入 R 正文時再次檢查有效期。

grant、claim 與實際引擎起跑是不同事件。過期而尚未執行、未知受理、模型失敗分開記帳。UNKNOWN 沿原 request／job 接回，不刪 claim、不換 ID 重發。此機制不是所有 xdev 任務的內建自動服務。

## 批次應留在 Windows

程式碼傳一次、資料在授權範圍內原地復用，Windows worker 執行整個已准入批次。Mac 一個低頻觀察器讀短進度；不要為每個短模型都重新啟動 R、打包與取回。

觀察時分開量測 grant 到提交、引擎起止、匯出、取回，以及工程準備時間。往返差值包含佇列、程序啟動、輪詢與打包，不是純網路延遲；單一成功區間的占比不代表相對本機開發的加速。

## 斷線與 worker 中斷

Mac 斷線或等待程序退出，不等於 Windows worker 已停止。先接原請求；worker 中斷時先核原引擎及孤兒輸出，避免已完成但未落回執的成員重跑。

原 cap 在判定成功前核一次，採用／匯出前再核。超時的 exit=0 仍按原合同記 TIMEOUT；未知耗時不能用 mtime 猜測或填零。無法結算的累計預算應保留 HOLD，不靜默擴大。

STOP 的語義由領域 worker 定義，例如當前成員按原 cap 收尾後停止新增；不是任意殺掉其他 owner 的 Mplus。資源等待不消耗引擎秒時，可按原合同等待合理時間，而非迅速整批失敗。

## 取回與驗收

先在 Windows 完成獨立讀取／統計核驗，再建結果匯出。`pull-dir` 會收整個指定目錄；逐項核 export manifest，取回後還要核實際檔案集合等於清單，避免預檢後混入輸入副本。

Windows 引擎完成、獨立核驗完成、Mac 取回完成是三種狀態。小回執與 SHA 摘要不等於完整取回；已完成結果不能因磁碟門檻未達而重跑。

Mac 回傳空間與 Windows 執行資源分別量測。記錄 Windows RAM／commit／C: 餘量，Mac 在取回前重新量測可用空間，保留專案規定的餘量。不要為了通過門檻擅自刪除他方資料或降低原科學精度。

## 大型歷史工作階段

已有快照時只取增量：先核舊快照前綴 SHA，檢查來源身分、大小及 mtime，再有界輸出增量；接收端以原快照與增量合算完整 SHA。來源變更或前綴不符時保留失敗，不拼出假完整紀錄。

機器內的私有原始紀錄與公開經驗摘要應分開。公開套件不包含 session、研究數值或真實資料。不要修改不透明的加密工作階段區塊來做正規表示式脫敏；發布整理過的明文經驗文件即可。

通道已可用後，慢收斂、負變異數與資訊矩陣異常要分別制定有限數值方案；不再把求解困難轉為持續修遠端工具。
