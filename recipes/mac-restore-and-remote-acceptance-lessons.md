# 配方：遷移恢復、空間治理與遠端驗收

[English validation guide](../docs/validation.md) · [研究批次](pp-lgcm-mplus-continuation.md)

此處只保留通用做法。大規模歸檔工具、雲端帳號與研究檔案不屬於 xdev 套件；按相應傳輸技能與使用者既有授權執行。

## 內容定址與 APFS 複製

分段恢復可先以 SHA 為鍵保存片段；單段檔案在同一支援 APFS clone 的卷內複製共享區塊，多段檔案則先拼接、核完整 SHA，再原子改名。每個目標檔依 manifest 回讀 SHA，通過條件應包括預期檔案集合與零壞件，不能僅看退出碼。

APFS clone 共享資料區塊，刪一份 clone 不代表回收它的邏輯大小。空間估算用實際可用量，不把 `du`、邏輯檔案大小及可回收實體大小混在一起。

## 有界預取

每個預取檔先持久占位，寫到獨立 `.partial`；整包 SHA 通過才改名就位。主恢復程序要辨識仍在更新的預取，避免同一包下載兩次。共用包的多個階段不要同時寫同一暫存檔。

增加並行未必提高總速度，可能只是瓜分帳號或出口帶寬。測總吞吐與暫存峰值，不只看單一串流。程式變更後從已核包邊界恢復，確保外層能區分「空間不足可續」與真實失敗，不能誤跳下一階段。

## 空間檢查與回收

取回前連續讀兩次可用空間，並為其他任務的瞬時寫入保留餘量。等待空間時，Windows 已完成的結果保持原樣，不重跑估計。Mac 與 Windows 的磁碟底線各自設定。

只在已授權範圍釋放可驗證冗餘副本：本地 SHA、回執 SHA 與預期 SHA 一致，且遠端精確物件仍存在且大小吻合。保存精確釋放清單；正在用的目錄、他方還原樹及有開啟句柄的檔案，不能因外觀像暫存就移除。

## 共享 Windows 引擎

先在 Mac 完成不呼叫引擎的編譯／合同檢查，準備原腳本與有限預算。真實估計依既有共享窗口先申請，獲准後確認沒有衝突引擎並立即提交；完畢寫原批次回執並釋放窗口。不要僅以當下 Mplus 程序為零，繞過仍有效的他方 grant。

聯絡其他 agent 使用已授權的協作機制，不自行往別人的輸入框注入命令。讓對方知道實際窗口起止、資源需求及是否有在途工作；不替他方取消、重提或停止作業。

## 接續大型工作階段

遷移快照可能早於源工作階段的最新寫入。先比大小、cutoff 與來源 SHA，必要時取有界增量；在新機直接恢復舊 session 的兼容性需另測。使用精簡交接定位，再按需讀原記錄，不重複載入全部歷史。

完整備份與公開文件是不同產物。公開時只提煉不含真實路徑、位址、token、研究數值與原始資料的經驗，不把私有歸檔或推理密文當作示例提交到 GitHub。
